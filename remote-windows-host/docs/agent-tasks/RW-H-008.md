# RW-H-008 — Portable catalog + launch services (H-CATALOG)

## Outcome
Implement the FR-01/FR-02 portable domain: `CatalogService` (scan → dedupe →
protocol-ready `app_catalog` snapshot) and `LaunchService` (allow-listed
`launch_app` by `app_id`, session tracking, liveness sweep → `app_status`),
plus `ControlServices` injection into the session handler so paired sessions
get a REAL catalog and REAL launch results instead of the empty /
`not_implemented` placeholders. Win32 scanning/launching is NOT this task
(that is RW-H-009); this task must be fully testable on macOS.

## Interface design (follow this; refine details, not the shape)

`core/catalog_service.hpp` — namespace `remotewindows::core`:

```cpp
// Pluggable catalog source (Win32 Start Menu walk = RW-H-009; tests use an
// in-memory fake). scan() runs on the calling thread.
class CatalogSource {
 public:
  virtual ~CatalogSource() = default;
  virtual std::vector<CatalogRecord> scan() = 0;
};

// Thread-safe (shared across per-connection worker threads).
class CatalogService {
 public:
  explicit CatalogService(CatalogSource* source);
  // First call or force_rescan -> source->scan() + merge into CatalogStore
  // (dedupe per core::dedupeCatalog semantics via CatalogStore::addOrUpdate).
  // Returns protocol-ready snapshot: catalog_revision = store revision,
  // entries mapped CatalogRecord -> protocol::AppEntry (source string ->
  // AppType: start_menu -> WIN32_SHORTCUT, packaged -> PACKAGED,
  // user_added -> USER_ADDED; anything else -> WIN32_SHORTCUT).
  protocol::AppCatalog snapshot(bool force_rescan = false);
  uint32_t revision() const;
  const CatalogRecord* find(const std::string& app_id) const;  // nullptr if absent
  // app_catalog_changed bookkeeping (heartbeat piggyback, see below).
  uint32_t lastBroadcastRevision() const;
  void markBroadcast(uint32_t revision);
 private:
  mutable std::mutex mu_;
  CatalogSource* source_;
  CatalogStore store_;
  bool scanned_ = false;
  uint32_t last_broadcast_ = 0;
};

// Launch requests carry ONLY catalog-resolved data (FR-02).
struct LaunchRequest {
  std::string app_id;
  std::string launch_target;  // from the catalog; never client input
  protocol::AppType type = protocol::AppType::WIN32_SHORTCUT;
};
struct LaunchOutcome {
  bool ok = false;
  std::string error_code;    // "" on success; e.g. "launch_failed"
  std::string safe_message;  // stable, user-safe; no paths, no OS raw errors
  uint32_t pid = 0;          // 0 = unknown
};
class AppLauncher {
 public:
  virtual ~AppLauncher() = default;
  virtual LaunchOutcome launch(const LaunchRequest& req) = 0;
};
class ProcessProbe {
 public:
  virtual ~ProcessProbe() = default;
  virtual bool isAlive(uint32_t pid) = 0;
};

struct LaunchSession {
  std::string app_id;
  std::string application_session_id;  // makeUuid()
  protocol::LaunchState state = protocol::LaunchState::UNSPECIFIED;
  uint32_t pid = 0;
  uint64_t started_ms = 0;
};

class LaunchService {
 public:
  LaunchService(const CatalogService& catalog, AppLauncher* launcher,
                ProcessProbe* probe, std::function<uint64_t()> now_ms = {});
  // Unknown app_id -> FAILED + error_code "unknown_app_id" and the launcher
  // is NEVER called. Unavailable entry -> FAILED + "launch_failed".
  // Launcher failure -> FAILED + launcher's error_code/safe_message.
  // Success -> new session (fresh uuid, state STARTED, pid from outcome),
  // result: state STARTED, application_session_id set, error_code "".
  // Re-launch of a still-live app_id is allowed (the launcher/OS decides
  // whether a second instance starts); the session record is replaced.
  protocol::LaunchResult handleLaunch(const std::string& app_id);
  // Sweep live sessions (state != CLOSED, pid != 0): dead process ->
  // state CLOSED; return one AppStatus{app_id, CLOSED, session_id} per
  // transition (each session is reported at most once).
  std::vector<protocol::AppStatus> sweep();
  const std::map<std::string, LaunchSession>& sessions() const;
 private:
  mutable std::mutex mu_;
  // members: catalog_ (ref), launcher_, probe_, now_ms_, sessions_ (by app_id)
};

// UUID-like v4: 8-4-4-4-12 lowercase hex, version nibble '4', variant in
// {8,9,a,b}; std::random_device based. Identity only, not a security token.
std::string makeUuid();
```

### SessionAuth injection (ORCH-granted scope)

```cpp
// SessionAuth.hpp
namespace remotewindows::core { class CatalogService; class LaunchService; }
// Shared cross-session services; nullptr = legacy placeholder behavior
// (empty catalog / not_implemented) so existing tests stay valid.
struct ControlServices {
  core::CatalogService* catalog = nullptr;
  core::LaunchService* launch = nullptr;
};
```

- `SessionAuth` ctor: append `ControlServices* services = nullptr`.
- `controlReply`:
  - `app_catalog_request` (paired): if `services_ && services_->catalog` →
    real `snapshot(force_rescan)` (force from the `AppCatalogRequest`
    payload); else the existing placeholder.
  - `launch_app` (paired): if `services_ && services_->launch` →
    `handleLaunch(app_id)`; else the existing placeholder.
- `heartbeat` (any state, thread-local piggyback — NO cross-connection
  writes; `net::Connection` is owned by its worker thread):
  - after the heartbeat reply, if `services_ && services_->catalog`:
    `rev != lastBroadcastRevision()` → `markBroadcast(rev)` + append an
    `app_catalog_changed` envelope (`catalog_revision = rev`).
  - if `services_ && services_->launch`: append one `app_status` envelope
    per `sweep()` result.
- `SignalingSessionHandler` ctor: append `ControlServices* services = nullptr`
  and pass it to the `SessionAuth` it creates.
- Structured logs (secret-free, stable fields): `session.catalog`
  (peer, entries, revision, force) and `session.launch` (peer, app_id,
  state, error). Never log launch targets, paths, codes, or keys.

## Acceptance criteria (verify on macOS; report exact commands + exit codes)

1. `cmake -S remote-windows-host -B remote-windows-host/build` and
   `cmake --build remote-windows-host/build -j` → exit 0 (run from the
   repo ROOT `/…/pc-coherence`, matching the existing build invocation in
   docs/STATUS.md; the build dir already exists — a fresh configure is fine
   if it is faster).
2. `ctest --test-dir remote-windows-host/build --output-on-failure` →
   ALL previously passing tests still pass (127 baseline) + the new tests,
   0 failures. Report the exact new total.
3. `catalog_service_test` covers at minimum:
   - snapshot after first request: entries deduped (two sources, same
     identity_key → one entry, higher priority wins), revision ≥ 1;
   - second non-forced request: no re-scan (fake source counts calls == 1),
     same revision;
   - forced re-scan with a changed source list: revision bumped,
     lastBroadcastRevision/markBroadcast transition observable;
   - `find()` by app_id hit/miss;
   - launch success: state STARTED, session id present (uuid format),
     session stored, `AppStatus` NOT yet emitted by sweep while probe alive;
   - launch unknown app_id: FAILED + `unknown_app_id`, fake launcher call
     count unchanged (allow-list proven);
   - launch unavailable entry: FAILED + `launch_failed`;
   - launcher failure: FAILED + launcher-provided error_code/safe_message;
   - sweep: probe reports dead → one `app_status` CLOSED with the session id;
     second sweep → empty (no duplicate events);
   - re-launch replaces the session (new session id, new pid);
   - `makeUuid`: exact format (36 chars, dash positions, version/variant
     nibbles) + 1000-sample uniqueness.
4. `session_auth_test`: at least one new e2e case over the real loopback
   server with `ControlServices` wired to fakes: pair → `app_catalog_request`
   → `app_catalog` containing the fake source's entries (assert app_id +
   display_name + type); and `launch_app` (known id) → `launch_result`
   STARTED with session id. Existing cases must pass unmodified.
5. No changes to `protocol/`, `AppController*`, `TrayController*`,
   `main.cpp`, new dependencies, or anything outside the write paths.
6. No protocol schema change is required (shapes already exist in v0.1.0).
   If you believe one is, STOP and report a CONTRACT_CHANGE_REQUEST instead
   of editing `protocol/`.
